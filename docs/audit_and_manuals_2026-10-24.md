# Часть 1. Что это

**Живой Код** — автономная машина кода на этой машине: одна цель — «одно хорошо написанное ТЗ → готовый проект» без человека в петле. Человек (владелец) пишет ТЗ; дальше машину ведут 30 кронов Hermes: кодеры пишут код, судьи проверяют, Владыка выносит вердикт, Продюсер выпускает релиз, граф эволюции (GodModeCoder) каждую ночь мутирует сами роли и промпты.

## 1.2 Поток одного цикла (упрощённо)

```
ТЗ владельца
   │
   ▼
[Кодеры] project1-4 — каждый час свой слот (03:00…22:00), 6 прогонов/день
   │  движок: FREE_POOL → модель → компиляция → малая карта → MD+PNG → 252
   ▼
[Судьи] профессор (*/30 мин), инквизитор (:35), супервизор (:45), искатель (:50)
   │  свои MD-отчёты → 252; оценки и замечания
   ▼
[Цикл-старт] каждые 4 часа (00:00, 04:00, …)
   │  git-sync очереди проектов → здоровье (laya/mem/disk/tmp)
   │  → сводка судей → хроника в журнал
   ▼
[Владыка] once-джоба после цикла
   │  должен записать строку «ВЕРДИКТ: <проект> — ГОРЯЧИЙ|ХОЛОДНЫЙ|ВЕРНУТЬ»
   ▼
[Продюсер] once-джоба
   │  при ГОРЯЧИЙ: cycle_close.py → копия проекта в Releases/<проект> → пуш → уведомление
   ▼
[Граф-пульс + экспортёр] 0 */4 — ночная эволюция графа, экспорт в Obsidian
```

## 3.4 Доставка отчётов — главное правило владельца

> **Отчёт сначала пишется в MD-файл (лучше с красивой картинкой), затем файл отправляется в группу 252.**

Реализация в `living_code_agent_wrapper.py → deliver_role_digest()`:
1. Тело слота (структурный парсер «СДЕЛАНО ЗА ЧАС / ПЛАН / ИЗМЕНЕНИЯ / ПРОВЕРКА КОДА»).
2. `reports/<роль>-<ГГГГММДД-ЧЧММ>.md` — заголовок с моделью и временем.
3. `→ .html` (тёмная GitHub-тема) → headless chromium → `.png` (высота по числу строк, до 8000 px).
4. `tg_send.py MEDIA:<md> <подпись>` → **sendDocument** в топик 252 от бота GodModeCoder.
5. `tg_send.py PHOTO:<png>` → **sendPhoto**-превью (пауза 2 с, ретрай при 429 с паузой 5 с).
6. Фолбэки: текстовый канал `_tg_deliver` → `hermes send`. Любой сбой доставки **не валид забег** — только метка в логе.

Использование tg_send.py вручную:
```bash
python3 scripts/tg_send.py "TEXT:Привет из терминала"
python3 scripts/tg_send.py "MEDIA:/путь/файл.md" "подпись"
python3 scripts/tg_send.py "PHOTO:/путь/превью.png" "подпись"
# цель по умолчанию: чат -1004431090317, топик 252; переопределение env TG_CHAT_ID/TG_THREAD_ID
# токен: TG_BOT_TOKEN env → профиль thomas → ~/.hermes/.env (движок всегда передаёт GodModeCoder явно)
```

## 3.5 Git и зеркала

**Точки**: локальный `~/LivingCode/orchestration` → `origin` = `DarkPushkin/living-code` (private, эталон) → `perfectfriend` = `PerfectFriend/living-code` (форк-зеркало) → флеш `…/living-code.git` (bare).

**Политика**: без force-push; только `git pull --rebase --autostash` → `git push`; флешка обновляется `fetch` из локального репо; секреты не коммитить.

**Трап двух аккаунтов**: в gh-ключнице активен **PerfectFriend**; приватные репо DarkPushkin из-за этого видны как «Repository not found». Глобально переключать аккаунт нельзя (машина пушит свои проекты как PerfectFriend). Пуш в DarkPushkin — прицельным helper:
```bash
git -c credential.helper= \
    -c credential.helper='!f() { echo "username=DarkPushkin"; echo "password=$(gh auth token --user DarkPushkin 2>/dev/null)"; }; f' \
    push origin main
```
(первый пустой `-c credential.helper=` обязателен — иначе твой helper добавится в конец списка и ключничный ответ выиграет).

**Обновление флеш-зеркала**:
```bash
M=/run/media/thomas/1c23f291-16dd-4af8-a9a9-0460511e75dd/living-code.git
git --git-dir="$M" fetch ~/LivingCode/orchestration '+refs/heads/*:refs/heads/*'
```

**Синк форка PerfectFriend**: `git push perfectfriend main` (пушится обычным helper'ом — активный аккаунт PerfectFriend).

## 3.6 Playbook: типовые поломки → лечение

| Симптом | Диагноз | Лечение |
|---|---|---|
| Кодер молчит, движок не стартует | Квоты/модели; крон-питон без модулей | Проверить `FREE_POOL` и `quota_exhausted`; в обёртках пин `~/build/bin/python3`; `hermes cron resume <id> --run-now` |
| MD не пришёл в 252 | tg_send упал | Прогнать вручную `tg_send.py MEDIA:…`; смотреть `[telegram]`-строки в выводе слота; при 429 — встроенный ретрай уже есть |
| PNG нет, MD есть | chromium не найден/упал | Проверить `which chromium`, env `CHROME_BIN`; превью опционально — доставка продолжается |
| Промоушен «неясно (Владыка не записал строку ВЕРДИКТ)» | Владыка не соблюдает формат | Усилить промпт `wrappers/prompts/lord_of_code.txt`; проверка строк — cycle_start_cron.py:111 (`ВЕРДИКТ: <проект> — ГОРЯЧИЙ/ХОЛОДНЫЙ/ВЕРНУТЬ`) |

# Часть 4. Руководство пользователя

## 4.1 Что ты видишь в Telegram-топике 252

- **Документ + фото-превью** после каждого слота кодера/судьи — файл MD можно открыть и прочитать полностью.
- Отчёты циклов (раз в 4 часа): синхронизация проектов, здоровье, промоушен.
- Никакой настройки не требуется: всё летит от бота GodModeCoder автоматически.

## 4.2 Как дать машине задание

1. **Пишешь ТЗ** — чем полнее, тем меньше итераций (цель, критерии готовности, что НЕ делать).
2. **Выбираешь кодера** под проект:
   - активные в ротации: project1–4, paranoidx;
   - спящие: `superguard`, `elemental-life`, `cybertarot`, `elemental-life-2` — триггер вручную.
3. **Триггеришь** (пример для спящего):
   ```bash
   hermes cron resume LV-coder-superguard --run-now
   ```
   После прогона once-джоб консервируется — для повтора снова resume+run-now.
4. Через 15–40 минут смотришь **документ в 252**: «СДЕЛАНО ЗА ЧАС / ПЛАН / ИЗМЕНЕНИЯ / ПРОВЕРКА КОДА».

## 4.3 Как читать вердикты и что происходит дальше

- После цикла Владыка выносит вердикт по каждому проекту: **ГОРЯЧИЙ** (готов — Продюсер выпустит релиз в `~/LivingCode/Releases/<проект>` и запушит), **ХОЛОДНЫЙ** (наблюдаем), **ВЕРНУТЬ** (доработка).
- Если в цикле видишь «неясно (Владыка не записал строку ВЕРДИКТ)» — промоушен не сработает; это текущая слабая точка (см. аудит §2.2).

## 4.4 Управление на ходу

| Хочу | Команда |
|---|---|
| Запустить кодера сейчас | `hermes cron resume LV-coder-project2 --run-now` |
| Запустить цикл немедленно | `hermes cron resume LV-cycle-start --run-now` |
| Поставить роль на паузу | `hermes cron pause LV-coder-project3` |

## 4.5 Чего машина ждёт от тебя (открытые пункты)

1. **Куки X** для искателя: `agent-reach configure twitter-cookies` (нужны `TWITTER_AUTH_TOKEN`, `TWITTER_CT0`).
2. **Решение по промоушену**: усилить формат вердиктов Владыки (п. 4.3) — тогда заработает автопилот «ГОРЯЧИЙ → релиз».
3. Спящие кодеры: сказать, кого вводить в ротацию.

## 4.6 FAQ

**Машина стучится каждую ночь — это нормально?** Да: ночные циклы — основное время эволюции; отчёты падают в 252, реакция не требуется.

**Кодер сделал не то.** Вернуть работу: напиши правку в ТЗ и триггери слот заново; судьи подхватят замечания в следующем цикле.

**Где лежит готовый проект?** Пока ни один не дошёл до релиза (`Releases/` пуст); рабочие версии — в `~/Projects/<проект>`.

**Отчёт пришёл без картинки?** PNG-превью опционально: если chromium не отрендерил, документ всё равно уходит.
